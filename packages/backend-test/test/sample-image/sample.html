assemblies-mapped.svg — hit-edge inspection

Move the mouse over the graph. Edges have padded polygon.hit-edge areas around them — they are easier to hit than the thin black line, and they scale with the SVG because they are part of the SVG itself.

What to look for

  • Each edge has a polygon.hit-edge drawn around it — wider than the black line, so it is easier to click or hover.
  • Hovering a hit-edge polygon draws a green border around it (sample.css).
  • The polygon carries data-from-id matching the edge's id, e.g. 1073741825||1073741829, so JavaScript could highlight the matching edge path on hover.

Why the edge path can't turn red from pure CSS

The hit-edge polygons are siblings of the edge groups inside <g id="graph0">. CSS has no parent selector and no way to match "the g.edge whose id equals this polygon's data-from-id". So making the edge path red on hit-edge hover requires either:

  • moving each hit-edge polygon inside its edge's g.edge group, then g.edge:hover path { stroke: red; } works, or
  • a small JavaScript handler that reads data-from-id and sets stroke: red on the matching path.
